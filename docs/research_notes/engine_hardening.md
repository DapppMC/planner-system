## Q1. SQLite WAL on WSL2 / DrvFs (/mnt/c) / Windows: what is and is not safe; placement; runtime detection

### Takeaway
WAL needs all connections to share one coherent mmap of the `-shm` file on one host; SQLite documents this only as "same host, no network filesystem". /mnt/c (DrvFs over 9p) and the `\\wsl.localhost\` UNC path are cross-VM, so one WAL database must never be opened by both Windows and Linux processes. Put the DB on a single OS side, on a local native FS (ext4 under `$HOME` in WSL2, or NTFS on Windows with only Windows processes), and verify at runtime that WAL actually engaged.

### Cited Findings
- "All processes using a database must be on the same host computer; WAL does not work over a network filesystem. This is because WAL requires all processes to share a small amount of memory and processes on separate host machines obviously cannot share memory with each other." — [SQLite WAL §1](https://www.sqlite.org/wal.html)
- "the use of shared memory means that all readers must exist on the same machine. This is why the write-ahead log implementation will not work on a network filesystem." — [SQLite WAL §2.2](https://www.sqlite.org/wal.html)
- The wal-index "is implemented using an ordinary file that is mmapped for robustness"; "The only way we have found to guarantee that all processes accessing the same database file use the same shared memory is to create the shared memory by mmapping a file in the same directory as the database itself." The wal-index is rarely above 32 KiB, never synced, and deleted when the last connection closes. — [SQLite WAL §7](https://www.sqlite.org/wal.html)
- The same page's chroot warning (different root => different shm => "database corruption") shows SQLite treats any context that does not share the same shm mapping as corrupting. — [SQLite WAL §7](https://www.sqlite.org/wal.html)
- The WAL page says nothing about VMs, WSL, 9p or DrvFs (I checked the fetched text). Whether a WSL2 VM counts as a "separate host" is therefore my inference, not an SQLite statement. — [SQLite WAL](https://www.sqlite.org/wal.html)
- Microsoft: "We recommend against working across operating systems with your files, unless you have a specific reason for doing so. For the fastest performance speed, store your files in the WSL file system if you are working in a Linux command line... If you're working in a Windows command line..., store your files in the Windows file system." Example: use `/home/<user name>/Project`, not `/mnt/c/Users/<user name>/Project`. — [Microsoft Learn: WSL file systems](https://learn.microsoft.com/en-us/windows/wsl/filesystems)
- Microsoft page does NOT mention DrvFs/9p, permissions or metadata, and has no SQLite statement; it says Windows is case-insensitive and Linux case-sensitive and points to a case-sensitivity article. — [Microsoft Learn: WSL file systems](https://learn.microsoft.com/en-us/windows/wsl/filesystems)
- WAL-reset corruption bug (relevant to 7 writers): present "from 3.7.0 (2010-07-21) through 3.51.2 (2026-01-09)", fixed in 3.51.3 (2026-03-13); backports 3.44.6 and 3.50.7. Affects WAL databases with two or more connections in separate threads or processes when they "attempt to write or checkpoint at the same instant". Rare ("not an emergency"), but a reproducer without special test hooks was published 2026-08-24 (Phil Eaton). — [SQLite WAL §11](https://www.sqlite.org/wal.html); independent confirmation that 3.51.2 fails and 3.51.3 passes a generic workload: [Antithesis](https://antithesis.com/blog/2026/wal-reset-bug/)
- WAL-mode read-only access needs existing readable `-shm`/`-wal`, or write permission on the directory, or `immutable` URI (SQLite >= 3.22.0). — [SQLite WAL §5](https://www.sqlite.org/wal.html)
- Third-party blog (low quality, uncited, author's own analysis) hints that Windows/WSL boundary paths like `\\wsl.localhost\...` change SQLite locking failure modes and that WAL "may not help" there. Treat as anecdote only. — [smartscope.blog](https://smartscope.blog/en/blog/codex-app-database-is-locked-wsl-fix-2026/)

### Inferences
Safe / unsafe matrix (derived from the SQLite shared-memory requirement + Microsoft guidance; not from an SQLite-published WSL statement):
- SAFE: all 7 processes native Windows, DB on local NTFS (not OneDrive/Dropbox-synced, not a network share).
- SAFE: all 7 processes inside one WSL2 distro, DB on ext4 (`/home/...`, `/tmp`, `/var/...`).
- SAFE-ish: all 7 processes inside WSL2 but DB on /mnt/c. Single kernel, but DrvFs/9p mmap/lock semantics are the weakest link; do NOT rely on it; also slow. Prefer ext4.
- UNSAFE (CRITICAL): some processes on Windows and some in WSL2 opening the same DB file (via /mnt/c or via `\\wsl.localhost\<distro>\home\...`). Two kernels = two independent mmap/lock domains, so the `-shm` wal-index is not shared coherently. Expect silent stale reads, lock failures, or corruption. No journal mode makes this fully safe; with `journal_mode=DELETE` the file locks (Windows LockFileEx vs POSIX fcntl through 9p) are only as good as the 9p translation, which I could not verify.
- UNSAFE: any network share (SMB/NFS/CIFS/sshfs/virtiofs-from-host), cloud-sync folders.
- `PRAGMA locking_mode=EXCLUSIVE` in WAL avoids shm but permits only one connection (from memory of the SQLite docs; not fetched), so it does not fit 7 processes.

Checklist:
1. [CRITICAL] Resolve the DB path with `os.path.realpath()` (follows symlinks/junctions) BEFORE checking, and check the real path, not the user-supplied one.
2. [CRITICAL] Linux/WSL2 detection: parse `/proc/self/mountinfo` (preferred; `/proc/mounts` also works), pick the mount with the longest prefix of the realpath, read its fstype field (field after the `-` separator). Treat as "unsafe for WAL" if fstype in {`9p`, `drvfs`, `cifs`, `smb3`, `nfs`, `nfs4`, `fuse.sshfs`, `fuse.*` generally, `virtiofs`, `vboxsf`, `afs`, `ncpfs`}. In WSL2 /mnt/c has typically shown as `9p` with `aname=drvfs` (recall; newer WSL builds may use virtiofs; not verified for Oct 2026). Detect WSL itself with `"microsoft" in os.uname().release.lower()` or `/proc/sys/fs/binfmt_misc/WSLInterop` existing or env `WSL_DISTRO_NAME`. `os.statvfs()` has no fs-type field in Python; either use mountinfo or `subprocess.run(["stat","-f","-c","%T",path])` (prints e.g. `ext2/ext3` for ext4, `v9fs`/`9p` for 9p; fallback only).
3. [CRITICAL] Windows detection with ctypes: `ctypes.windll.kernel32.GetDriveTypeW(ctypes.c_wchar_p(root))` where `root` = `os.path.splitdrive(os.path.realpath(p))[0] + "\\"`; return value 4 = `DRIVE_REMOTE` => unsafe; 3 = `DRIVE_FIXED` OK; also reject any path starting with `\\` or `\\?\UNC\` or `\\wsl$` / `\\wsl.localhost` (UNC, 9p-backed). Mapped drives and `subst` drives resolve via `os.path.realpath` (3.8+) on most cases; verify with a test. Also warn when the path sits under a OneDrive/Dropbox/Google Drive folder (HIGH, heuristic by directory name / `%OneDrive%` env).
4. [CRITICAL] Cross-OS guard: if running in WSL2 and path starts with `/mnt/<letter>/`, or running on Windows and path is a `\\wsl...` UNC, hard fail with an explanatory message and the recommended location (`$HOME/.cache/<app>/blackboard.db` in WSL; `%LOCALAPPDATA%\<app>\` on Windows).
5. [CRITICAL] After `PRAGMA journal_mode=WAL;` check the returned row: `cur.execute("PRAGMA journal_mode=WAL").fetchone()[0].lower() == "wal"`. The pragma returns the resulting mode and returns the old mode (e.g. `delete`) when the change is refused; never assume success. (Recall from SQLite pragma docs, not re-fetched.) Fail loudly, or fall back deliberately.
6. [HIGH] Fallback design if the FS is unsafe: either (a) refuse (recommended for the sealed protocol), or (b) `PRAGMA journal_mode=DELETE` plus an advisory process lock file (`os.open(lock, O_CREAT|O_EXCL)` with pid+start-time contents, or `msvcrt.locking` / `fcntl.flock`). Mark (b) "degraded, single-writer-at-a-time, for dev only"; flock/LockFileEx semantics over 9p are unverified.
7. [HIGH] Minimum SQLite version gate: `sqlite3.sqlite_version_info >= (3,51,3)` or (3,50,7)+ on the 3.50 line or (3,44,6)+ on the 3.44 line; otherwise log WARN (Linux distro libs and python.org installers bundle different versions; Windows python.org builds ship their own SQLite per Python patch release; Linux uses the system lib). With 7 writer processes this bug's trigger (concurrent write/checkpoint) is in scope. No documented workaround other than upgrading (Antithesis and SQLite both say so).
8. [HIGH] Keep the DB, `-wal` and `-shm` in one directory on one FS; never copy the `.db` alone while connections are open (copy via `sqlite3.Connection.backup()` or `VACUUM INTO`). Never delete `-shm`/`-wal` while any process is open.
9. [MEDIUM] Do not place the DB inside the worktree that the sealed gate copies/zips; exclude `*.db`, `*.db-wal`, `*.db-shm` in the copy `ignore`.

### Gaps
- No primary-source (SQLite or Microsoft) statement on WAL over DrvFs/9p/`\\wsl.localhost` found; web search for the microsoft/WSL issue tracker returned only unrelated hits. The unsafe verdict for cross-VM sharing is inference from the shm/mmap requirement.
- Not verified: fstype string for /mnt/c on current (Oct 2026) WSL builds (9p vs virtiofs); whether `GetDriveTypeW` reports `\\wsl.localhost` paths as DRIVE_REMOTE (UNC roots need `GetDriveTypeW(r"\\wsl.localhost\Ubuntu\")`); SQLite `useovernet.html` and `howtocorrupt.html` were not fetched.

## Q2. Python `sqlite3` transaction semantics, busy handling, checkpoints, durability, threads, fork

### Takeaway
Use one connection per process opened after process start, `isolation_level=None` with `timeout=` set, and explicit `BEGIN IMMEDIATE` for every transaction that may write (this makes SQLite call the busy handler instead of failing instantly on a stale read snapshot). Do not pass `autocommit=` (3.12+ only) and do not set it to False. Keep read transactions short to avoid checkpoint starvation.

### Cited Findings
- Python 3.12 added `Connection.autocommit` with three values: `False` (PEP 249 behaviour, "sqlite3 ensures a transaction is always open", recommended by the docs), `True` (SQLite autocommit, "`commit()` and `rollback()` have no effect"), and `sqlite3.LEGACY_TRANSACTION_CONTROL` (pre-3.12 behaviour, "currently the default"; "The default will change to `False` in a future Python release"). — [Python sqlite3 docs](https://docs.python.org/3/library/sqlite3.html)
- "The `isolation_level` attribute has no effect unless `autocommit` is `LEGACY_TRANSACTION_CONTROL`". `isolation_level=None` means "transactions are never implicitly opened"; default `""` aliases `"DEFERRED"`. — [Python sqlite3 docs](https://docs.python.org/3/library/sqlite3.html)
- Under legacy control with a non-None isolation_level, an implicit transaction is opened before INSERT/UPDATE/DELETE/REPLACE if none is open. — [Python sqlite3 docs](https://docs.python.org/3/library/sqlite3.html)
- `timeout` (float, default 5 seconds): "How many seconds the connection should wait before raising an `OperationalError` when a table is locked." — [Python sqlite3 docs](https://docs.python.org/3/library/sqlite3.html)
- `check_same_thread=True` (default) raises `ProgrammingError` if another thread uses the connection; if False "write operations may need to be serialized by the user". `sqlite3.threadsafety` is set dynamically since 3.11: 0 single-thread, 1 modules shared but not connections (SQLITE_THREADSAFE=2), 3 connections and cursors shareable (serialized, SQLITE_THREADSAFE=1). — [Python sqlite3 docs](https://docs.python.org/3/library/sqlite3.html)
- SQLite: "DEFERRED ... Subsequent write statements will upgrade the transaction to a write transaction if possible, or return SQLITE_BUSY." "IMMEDIATE causes the database connection to start a new write immediately... might fail with SQLITE_BUSY if another write transaction is already active." "EXCLUSIVE and IMMEDIATE are the same in WAL mode". A read transaction sees "an historic snapshot" and if another connection modified the DB, "upgrading to a write transaction is not possible and the write statement will fail with SQLITE_BUSY". — [SQLite lang_transaction](https://www.sqlite.org/lang_transaction.html)
- "since there is only one WAL file, there can only be one writer at a time." — [SQLite WAL §2.2](https://www.sqlite.org/wal.html)
- Checkpointing: auto-checkpoint on COMMIT when WAL reaches 1000 pages (about 4 MB) via `wal_autocheckpoint`; a checkpoint cannot reset the WAL while any reader holds it; with "many concurrent overlapping readers and... always at least one active reader... the WAL file will grow without bound". Checkpoint "does not normally truncate the WAL file (unless the journal_size_limit pragma is set)". Remedies: `SQLITE_CHECKPOINT_RESTART` / `SQLITE_CHECKPOINT_TRUNCATE` manual checkpoints (readers may block while it runs). — [SQLite WAL §2.1, §3.1, §6](https://www.sqlite.org/wal.html)
- Durability: with `PRAGMA synchronous=NORMAL` in WAL, writers do not sync on commit; "the checkpoint is the only operation to issue an I/O barrier"; transactions "are no longer durable and might rollback following a power failure or hard reset"; FULL syncs the WAL every commit. — [SQLite WAL §2.3](https://www.sqlite.org/wal.html)

### Inferences
Checklist:
1. [CRITICAL] Connection factory valid on 3.10-3.13: `sqlite3.connect(path, timeout=30.0, isolation_level=None, check_same_thread=True)`. This runs in pure autocommit under the legacy mode on 3.10/3.11/3.12/3.13, with no `autocommit=` kwarg (the kwarg raises `TypeError` before 3.12). If you ever pass `autocommit=False` on 3.12+, Python opens a transaction implicitly and your `BEGIN IMMEDIATE` fails with "cannot start a transaction within a transaction". If you choose `autocommit=True` (3.12+ only), explicit `BEGIN`/`COMMIT` still work; gate it behind `sys.version_info >= (3, 12)`.
2. [CRITICAL] Write helper pattern: `con.execute("BEGIN IMMEDIATE")`; `try: ...; con.execute("COMMIT") except BaseException: con.execute("ROLLBACK") if con.in_transaction; raise`. Check `con.in_transaction` (works in all versions) before ROLLBACK. Never rely on `con.commit()` in autocommit mode.
3. [CRITICAL] Start every read-modify-write with BEGIN IMMEDIATE, never DEFERRED; a deferred read-then-write that races a committed writer gets SQLITE_BUSY (BUSY_SNAPSHOT) that cannot be cured by waiting, because the snapshot is stale. Pure reads (cursor polling) may use a plain autocommit SELECT.
4. [HIGH] Busy handling: `timeout=` and `PRAGMA busy_timeout=<ms>` set the same per-connection busy handler (last one wins); set both consistently: `con.execute("PRAGMA busy_timeout=30000")`. Catch `sqlite3.OperationalError`; on 3.11+ use `e.sqlite_errorcode` / `e.sqlite_errorname` (`SQLITE_BUSY`=5, `SQLITE_LOCKED`=6, `SQLITE_BUSY_SNAPSHOT`) rather than string matching "database is locked". Retry loop with jittered exponential backoff (e.g. 3-5 attempts around BEGIN IMMEDIATE only), then surface the error. The busy handler is not a fairness queue: 7 writers can starve one; keep write transactions to milliseconds (no network, no subprocess, no file I/O inside).
5. [HIGH] Per-connection PRAGMAs, executed on every new connection: `busy_timeout`, `synchronous`, `foreign_keys=ON`, `wal_autocheckpoint`, `journal_size_limit`. `journal_mode=WAL` is persistent in the file, run once at init (and itself may hit BUSY, so wrap in the retry).
6. [HIGH] Checkpoint policy: leave `wal_autocheckpoint=1000` default, set `PRAGMA journal_size_limit=67108864` (64 MiB) so a checkpoint-restart shrinks the WAL, and have one maintenance worker run `PRAGMA wal_checkpoint(TRUNCATE)` periodically (e.g. every 60 s, or when `-wal` > N MB); the pragma returns `(busy, log, checkpointed)`; busy=1 means it could not finish, log the count and retry later. Starvation cause in Python: unfinished SELECT cursors keep a read transaction open; always `fetchall()` or `cur.close()`; never hold a cursor across a `sleep`/heartbeat tick; the 7 workers' long-lived "tailing" reads must be re-queried, not kept open.
7. [HIGH] Durability choice: `synchronous=NORMAL` (default recommendation for a blackboard whose state is recoverable: app crash safe, may lose last commits on power loss/OS crash, and the DB cannot corrupt from this in WAL); `FULL` only if lost leases/events after power loss are unacceptable (cost: fsync per commit; on Windows FlushFileBuffers is slow). Leases are ephemeral, so NORMAL is fine; document that a power loss can resurrect old lease/cursor state, which fencing tokens must tolerate.
8. [HIGH] One connection per process, created AFTER the process starts. Never share a connection across `os.fork()` (SQLite advises against carrying an open connection across fork; recalled from `howtocorrupt.html`, not fetched). Linux `multiprocessing` default is `fork` through 3.13 (default changes to `forkserver` in 3.14, outside this range; recall) and Windows/macOS use `spawn`, so create connections inside the worker function, not at import time/module level. Use `os.register_at_fork(after_in_child=...)` to drop an inherited connection if a library forks.
9. [MEDIUM] Threads: keep `check_same_thread=True` and one connection per thread (the docs' `threadsafety==1` level is the common one); if the heartbeat is a thread, give it its own connection.
10. [MEDIUM] Always `con.close()` in `finally`; on Windows open handles block deleting the DB/temp dir (see Q6).
11. [MEDIUM] Add a startup `PRAGMA quick_check` or `integrity_check` option for the maintenance worker only (cost scales with DB size).

### Gaps
- Python docs "Transaction control" explanation section was beyond the truncated fetch; the BEGIN IMMEDIATE-with-isolation_level=None recipe is from my knowledge, consistent with the quoted attribute docs.
- The claim that the busy handler is not invoked for stale-snapshot upgrade failures is from SQLite knowledge (SQLITE_BUSY_SNAPSHOT); lang_transaction as fetched states the upgrade fails with SQLITE_BUSY but does not mention the busy handler.
- `sqlite_errorcode` / `sqlite_errorname` (3.11) are from recall of the Python changelog; not re-fetched.

## Q3. Clocks, leases with fencing tokens, crash recovery, AUTOINCREMENT event cursors

### Takeaway
All 7 processes share one host, so `time.time()` has zero inter-process skew; the real risks are wall-clock jumps and coarse resolution, not skew. Use a single wall-clock source in integer milliseconds stored in the DB, with margins, plus a per-path fencing token incremented inside the same BEGIN IMMEDIATE transaction that grants the lease. Premise check: in SQLite, event ids ARE allocated in commit order (single writer), so the Postgres-style "late-commit visibility gap" does not occur within one SQLite file; keep the defensive cursor rules anyway.

### Cited Findings
- `time.monotonic()`: "The reference point of the returned value is undefined, so that only the difference between the results of two calls is valid." Changed in 3.5: "the clock is now the same for all processes"; changed in 3.10: "On macOS, the clock is now the same for all processes." Windows source is `QueryPerformanceCounter()`/`QueryPerformanceFrequency()`; Linux `clock_gettime(CLOCK_MONOTONIC)`. — [Python time docs](https://docs.python.org/3/library/time.html)
- `time.time()`: "can return a lower value than a previous call if the system clock has been set back"; on Windows it calls `GetSystemTimePreciseAsFileTime()` since 3.13 ("Changed in version 3.13... instead of `GetSystemTimeAsFileTime()`"). `time.perf_counter()` uses the same clock as `monotonic()` since 3.13. `time.get_clock_info('time')` exposes `.adjustable`, `.implementation`, `.monotonic`, `.resolution`. — [Python time docs](https://docs.python.org/3/library/time.html)
- Only one writer at a time; BEGIN IMMEDIATE takes the write lock at once and may fail with SQLITE_BUSY if another write transaction is active. — [SQLite WAL §2.2](https://www.sqlite.org/wal.html), [SQLite lang_transaction](https://www.sqlite.org/lang_transaction.html)
- The page I fetched for `os.kill` was truncated; the Windows `os.kill` behaviour could not be quoted (see Gaps). Python's `Popen` docs state `CREATE_NEW_PROCESS_GROUP` "is necessary for using `os.kill()` on the subprocess" and that on Windows `kill()` is an alias for `terminate()` (`TerminateProcess()`). — [Python subprocess docs](https://docs.python.org/3/library/subprocess.html)

### Inferences
Clock rules:
1. [CRITICAL] Do not store `time.monotonic()` values in the DB and compare them across processes unless you also store a boot identity; its reference is undefined, it is system-wide on 3.5+/3.10+ per docs but resets on reboot and (Linux CLOCK_MONOTONIC) does not count suspend. For a cross-process lease table on one host, store wall-clock `expires_at_ms = int(time.time()*1000) + ttl_ms` and compare to `int(time.time()*1000)` read at decision time inside the BEGIN IMMEDIATE txn. (Alternative: derive "now" from SQLite itself, `SELECT CAST(strftime('%s','now') AS INTEGER)*1000 + ...`, but that is the same system clock and only gives second/ms strings; no benefit.)
2. [HIGH] Treat wall-clock jumps as the failure mode: a backward NTP step or manual change lengthens leases; a forward jump expires them early. Mitigations: (a) the lease holder decides locally with `time.monotonic()` whether it still believes it holds the lease (stop work when `monotonic() - last_successful_renew > ttl*0.66`), (b) the DB expiry is only the reclaim signal for others, (c) add a skew margin (e.g. reclaim only when `now > expires_at + grace_ms`, grace = 2 s) and (d) detect jumps: sample `abs((time.time()-t0)-(time.monotonic()-m0)) > 1.0` in the heartbeat and log/raise. Never use sleep deltas from `time.time()`.
3. [MEDIUM] Windows resolution: before 3.13 `time.time()` used `GetSystemTimeAsFileTime` (typically a ~15.6 ms system tick, often cited; the docs page gives no number, so unverified); from 3.13 it uses the precise variant (sub-microsecond granularity claimed by Windows API, not by Python docs). Therefore: store integer milliseconds, never compare timestamps for equality or rely on strict ordering of `time.time()` values across processes, order by DB-assigned `id` instead. Probe with `time.get_clock_info("time").resolution` in the self-test and log it.
4. [MEDIUM] WSL2 has its own known clock drift after host sleep/hibernate (recall; not verified): a reason to keep all processes inside one OS and tolerate jumps.

Lease schema and protocol (single DB, all in `BEGIN IMMEDIATE`):
```
CREATE TABLE lease(path TEXT PRIMARY KEY, owner TEXT NOT NULL, fence INTEGER NOT NULL,
                   expires_at_ms INTEGER NOT NULL, heartbeat_at_ms INTEGER NOT NULL);
```
5. [CRITICAL] Acquire: in one txn read row; if absent, or `expires_at_ms + grace < now`, or `owner == me`: `fence = (old_fence or 0) + 1`, upsert row. Never DELETE the lease row on release (set `expires_at_ms=0`), otherwise the per-path counter resets and fences repeat. Alternative global monotonic fence: use `INSERT INTO fence_seq DEFAULT VALUES` (AUTOINCREMENT) or the events table id inside the same txn; a global counter is simpler and unique.
6. [CRITICAL] Renew/heartbeat: `UPDATE lease SET expires_at_ms=?, heartbeat_at_ms=? WHERE path=? AND owner=? AND fence=? AND expires_at_ms>?` then check `cur.rowcount == 1`; zero rows => lease lost, worker must stop and discard work. Renew at TTL/3. TTL should be many multiples of worst-case busy wait (timeout 30 s => TTL >= 60-90 s) or a slow DB makes healthy workers lose leases.
7. [CRITICAL] Fencing enforcement: every state-changing write the holder makes (events insert, status update) is done as `... WHERE EXISTS (SELECT 1 FROM lease WHERE path=? AND owner=? AND fence=? )` inside the same BEGIN IMMEDIATE txn, and the token is stored in the row (`events.fence`). A stale worker whose lease was reclaimed then fails the check. LIMITATION (state in spec): fencing only protects state inside the DB; a zombie that already holds the filesystem path can still write files in the worktree, because the filesystem does not check tokens. Mitigate by having the worker re-check its lease immediately before and after each file write batch and by atomic publish (write temp + `os.replace` only after a fence check).
8. [HIGH] Crash recovery: TTL expiry is sufficient and the only portable mechanism. Optional accelerator: store `pid` and process start time; the reaper checks liveness. Do NOT use `os.kill(pid, 0)` on Windows: on Windows, `os.kill` with any signal other than `CTRL_C_EVENT`/`CTRL_BREAK_EVENT` calls `TerminateProcess` (my recall of the os docs; fetch truncated, unverified), so a "liveness probe" could kill the target. Use `ctypes` `OpenProcess(PROCESS_QUERY_LIMITED_INFORMATION=0x1000, ...)` + `GetExitCodeProcess == STILL_ACTIVE(259)` on Windows, `os.kill(pid, 0)` only on POSIX (PermissionError means alive). PID reuse: pair pid with start time.
9. [MEDIUM] Release: `UPDATE ... SET expires_at_ms=0 WHERE path=? AND owner=? AND fence=?` in `finally`; reaper `UPDATE` for expired rows is unnecessary because acquire already treats expired as free; add an `idx_lease_expires` only if scans occur.

Events and cursors:
10. [HIGH] Why the "late-commit gap" does not bite SQLite (inference, reasoned from the one-writer rule): in Postgres/MySQL a sequence value is taken at INSERT time but made visible at COMMIT, so txn A (id 5) can commit after txn B (id 6); a reader that saw 6 and set cursor=6 skips 5 forever. In SQLite the rowid/AUTOINCREMENT value is chosen while holding the single write lock, which is held until COMMIT/ROLLBACK, so ids become visible in the order allocated. Gaps arise only from ROLLBACKs (harmless) and AUTOINCREMENT never reuses ids. Caveats where the gap DOES reappear: (a) cursor on `ts` or any app-computed value instead of `id`; (b) explicit ids supplied by the app; (c) events written to several DB files, or a later migration to Postgres; (d) cursor computed from a separate `SELECT MAX(id)` outside the reader's snapshot.
11. [HIGH] Cursor rules: cursor = `max(id)` of the rows actually returned by the same statement (`SELECT ... WHERE id > ? ORDER BY id LIMIT n`); persist the cursor update in the same BEGIN IMMEDIATE txn as any state effect for at-least-once with idempotent handlers (dedupe by event id); never advance to a separately read `MAX(id)`.
12. [HIGH] Generic fix if the late-commit gap is ever a concern: (i) allocate ids through a single-row counter table `UPDATE seq SET n=n+1 RETURNING n` inside the same write txn (same ordering guarantee), or (ii) consumers re-read an overlap window `id > cursor - W` and dedupe by id, or (iii) a "safe horizon" (only consume ids older than the oldest in-flight writer's start), or (iv) transactional outbox. In SQLite plain AUTOINCREMENT + rule 11 is enough; add a concurrency stress test (7 procs x N inserts, readers assert no skipped ids except rolled-back ones).
13. [MEDIUM] Use `INTEGER PRIMARY KEY AUTOINCREMENT` (monotonic, uses `sqlite_sequence`, no reuse after pruning the tail) rather than bare rowid: without AUTOINCREMENT, after deleting the highest row, the next insert can reuse its id and a cursor positioned at the old max would skip the new event. Pruning old events (retention) is then safe if every cursor is below `min(cursor)`; store a `pruned_below_id` marker so a lagging worker detects it.

### Gaps
- Exact Windows `time.time()` resolution on pre-3.13 Pythons was not found in Python docs (only the API switch in 3.13); the ~15.6 ms figure is from recall.
- `os.kill` Windows semantics not verified from the fetched docs (page truncated before it).
- Whether QPC/`CLOCK_MONOTONIC` survive WSL2 suspend consistently: not verified.
- The claim "SQLite ids are visible in allocation order" is reasoned from documented one-writer semantics, not stated verbatim in SQLite docs; recommended to prove with the stress test.

## Q4. Path normalisation across Windows / WSL2 / Linux

### Takeaway
Lowercasing all paths is wrong on case-sensitive Linux trees (collapses `README` and `readme`) and insufficient on Windows. Normalise to a canonical *key* per platform and keep the original spelling; make case-folding a property of the target filesystem (detected at runtime), not of the OS name.

### Cited Findings
- "Windows is case-insensitive and Linux is case-sensitive" (WSL doc; per-directory case sensitivity is adjustable in WSL via a separate article that was not fetched). — [Microsoft Learn: WSL file systems](https://learn.microsoft.com/en-us/windows/wsl/filesystems)
- Microsoft recommends staying on one OS's file system (see Q1); `/mnt/c` is a mounted Windows drive. — [Microsoft Learn: WSL file systems](https://learn.microsoft.com/en-us/windows/wsl/filesystems)
- No other path claims were verified from sources this session.

### Inferences (all from recall of Python/Windows behaviour, not re-fetched)
1. [CRITICAL] Do not blanket `.lower()`. Two modes: `case_sensitive_fs` detected by creating a probe file `.CaseProbe` in the root and checking `os.path.exists(".caseprobe")` (also covers WSL per-directory case sensitivity and macOS). Use `os.path.normcase` only on Windows (it lowercases and converts `/` to `\`), and prefer `str.casefold()` for the comparison key on case-insensitive volumes. Lease key = `(volume_id, normalised_relpath)`; store the original too.
2. [CRITICAL] Compute lease keys from paths relative to a canonical worktree root: `rel = os.path.relpath(os.path.realpath(p), os.path.realpath(root))`; reject if `rel` starts with `..` or equals `..`, or is absolute / has a different drive (`ValueError` on Windows relpath across drives). Use `pathlib.PurePosixPath` for the stored key (always `/`), converting from `PureWindowsPath` first. Check containment with `os.path.commonpath([root, p]) == root` after realpath, not with `startswith` (prefix bug: `/a/b` vs `/a/bc`).
3. [HIGH] Windows specifics to reject or normalise: trailing dots and spaces (silently stripped by Win32 so `a.txt.` aliases `a.txt`); reserved device names `CON, PRN, AUX, NUL, COM1-9, LPT1-9` (also with extension, e.g. `nul.txt`) — Python 3.13 added `os.path.isreserved()` and `pathlib.PureWindowsPath.is_reserved()` (recall; verify) — alternate data streams `file.txt:stream`; 8.3 short names (`PROGRA~1`) alias long names: resolve with `ctypes.windll.kernel32.GetLongPathNameW` or `os.path.realpath` (does not always expand 8.3, unverified); drive-relative paths `C:foo`; `\\?\` and `\\.\` prefixes: strip/normalise via `os.path.realpath` (3.8+ handles `\\?\`), and use `\\?\` + absolute path only for I/O beyond MAX_PATH (260) when LongPathsEnabled is not set (Python 3.6+ on Win10 1607+ honours the registry long-path flag only if the app manifest opts in; python.exe's manifest does, recall); treat any `:` in a relative key as invalid.
4. [HIGH] Symlinks/junctions: `os.path.realpath` follows symlinks and junctions on Windows 3.8+; compare realpaths before leasing so a symlink cannot alias two lease keys; reject links that leave the root. `Path.is_junction()` exists in 3.12+ (recall); on older versions use `os.lstat().st_reparse_tag` (Windows 3.8+? recall) or just rely on realpath.
5. [HIGH] Unicode: macOS (HFS+/APFS-normalising) stores NFD; Linux/NTFS store as given. Key = `unicodedata.normalize("NFC", s)` before casefold; keep original for I/O. Beware `str.casefold()` vs NTFS's own upcase table: they differ for rare characters (e.g. `ß`, Turkish dotless i); collisions are then possible but acceptably safe-by-over-locking.
6. [MEDIUM] WSL: paths from Windows tools arrive as `C:\...` or `\\wsl.localhost\...`; translate only at the boundary with `wslpath -u/-w` (subprocess), never by string hacking; store only POSIX-style relative keys.
7. [MEDIUM] Reject NUL bytes and control chars in keys; cap key length; do not use `os.path.abspath` for security decisions (does not resolve symlinks); `..` collapse via `normpath` can be wrong across symlinks, so resolve first.

### Gaps
- No primary-source verification of any Windows path-semantics claim (reserved names, 8.3, `\\?\`, `os.path.isreserved` in 3.13, `Path.is_junction` in 3.12); all from recall.
- Microsoft's per-directory case-sensitivity article was not fetched.

## Q5. Sealed gate: subprocess timeouts, process-tree kill, output capture, encoding, env scrubbing, pytest invocation, exit codes

### Takeaway
`subprocess.run(timeout=)` kills only the direct child. Use `Popen` in its own process group/session (POSIX `start_new_session=True` + `os.killpg`) or its own Job Object / `taskkill /F /T` (Windows), drain pipes via `communicate()` or temp files, and treat pytest exit code 5 (and an empty/absent junit XML) as FAIL, never pass.

### Cited Findings
- `subprocess.run`: "If the timeout expires, the child process will be killed and waited for. The `TimeoutExpired` exception will be re-raised after the child process has terminated." The docs do not mention grandchildren. — [Python subprocess docs](https://docs.python.org/3/library/subprocess.html)
- `Popen.communicate(timeout)`: "The child process is not killed if the timeout expires"; recommended pattern: `proc.kill(); outs, errs = proc.communicate()`; "After a call to `communicate()` raises `TimeoutExpired`, do not call `wait()`. Use an additional `communicate()` call to finish handling pipes." "Catching this exception and retrying communication will not lose any output." — [Python subprocess docs](https://docs.python.org/3/library/subprocess.html)
- `TimeoutExpired.output` is "always `bytes` when any output was captured regardless of the `text=True` setting" and "may remain `None` instead of `b''`". — [Python subprocess docs](https://docs.python.org/3/library/subprocess.html)
- `start_new_session=True` calls `setsid()` in the child (POSIX); `process_group` (int) calls `setpgid(0, value)` (POSIX, added 3.11). — [Python subprocess docs](https://docs.python.org/3/library/subprocess.html)
- `CREATE_NEW_PROCESS_GROUP` "is necessary for using `os.kill()` on the subprocess"; `CTRL_BREAK_EVENT` can be sent to such processes via `send_signal`. On Windows `kill()` is an alias for `terminate()` which calls `TerminateProcess()`; on POSIX `kill()` sends SIGKILL, `terminate()` SIGTERM. — [Python subprocess docs](https://docs.python.org/3/library/subprocess.html)
- Pipe deadlock: `wait()` "will deadlock when using `stdout=PIPE` or `stderr=PIPE` and the child process generates enough output"; use `communicate()`; do not use `.stdout.read` with another pipe also open. — [Python subprocess docs](https://docs.python.org/3/library/subprocess.html)
- pytest exit codes: 0 all passed; 1 tests ran, some failed; 2 interrupted by user; 3 internal error; 4 command-line usage error; 5 "No tests were collected". — [pytest exit codes](https://docs.pytest.org/en/stable/reference/exit-codes.html)
- pytest plugin loading: `-p no:name` blocks a plugin (even builtin) before normal arg parsing; `-p name` loads early; entry-point (`pytest11`) plugins load "unless the `PYTEST_DISABLE_PLUGIN_AUTOLOAD` environment variable is set"; `PYTEST_PLUGINS` env plugins load after entry points. The page does not cover `--noconftest`. — [pytest: writing plugins](https://docs.pytest.org/en/stable/how-to/writing_plugins.html)
- `tempfile.TemporaryDirectory(suffix, prefix, dir, ignore_cleanup_errors=False, *, delete=True)`: `ignore_cleanup_errors` added in 3.10 ("such as a `PermissionError` removing open files on Windows... best-effort"); `delete` added in 3.12. — [Python tempfile docs](https://docs.python.org/3/library/tempfile.html)

### Inferences
Checklist:
1. [CRITICAL] POSIX (Linux/WSL2): `p = subprocess.Popen(cmd, stdout=f_out, stderr=f_err, stdin=subprocess.DEVNULL, cwd=sandbox, env=clean_env, start_new_session=True)`; on timeout `os.killpg(p.pid, signal.SIGTERM)`, wait ~3-5 s via `p.wait(timeout=...)`/poll, then `os.killpg(p.pid, signal.SIGKILL)`, then `p.communicate()`/`p.wait()` to reap. (`process_group=0` on 3.11+ is lighter, `start_new_session=True` works on 3.10 and also detaches from the controlling TTY, which is what you want for a sandbox.) Guard `ProcessLookupError`. Note killpg only reaches descendants that stayed in the group; a child calling `setsid`/`setpgid` escapes; for hard guarantees on Linux use a cgroup/`prctl(PR_SET_CHILD_SUBREAPER)` (out of stdlib scope) or sweep by scanning `/proc` for processes whose cwd/env marker points into the sandbox dir (add `GATE_SANDBOX_ID=<uuid>` to env and sweep).
2. [CRITICAL] Windows: `creationflags = subprocess.CREATE_NEW_PROCESS_GROUP | subprocess.CREATE_NO_WINDOW`; on timeout run `subprocess.run(["taskkill","/F","/T","/PID",str(p.pid)], capture_output=True)` (kills the tree by parent links; fails to catch grandchildren whose parent already exited), then `p.communicate()`. Stronger: a Job Object via ctypes — `CreateJobObjectW`, `SetInformationJobObject(JobObjectExtendedLimitInformation=9)` with `JOB_OBJECT_LIMIT_KILL_ON_JOB_CLOSE=0x2000`, `AssignProcessToJobObject(job, int(p._handle))` immediately after `Popen` (small race: child can spawn before assignment; use `CREATE_SUSPENDED` is not exposed in `subprocess`, so accept the race or use `taskkill` as backup), then `TerminateJobObject(job, 1)` on timeout. Jobs nest on Windows 8+, so it works even if the gate itself runs in a job.
3. [CRITICAL] Redirect stdout/stderr to temp files (not PIPEs) when you need partial output after a kill: no pipe-buffer deadlock, output survives the kill, and a surviving grandchild that inherited the pipe write end cannot block `communicate()` forever (this is the classic hang: after `p.kill()`, `communicate()` still waits on a pipe held open by an orphaned grandchild). If PIPE is used, call `communicate(timeout=5)` after the kill and abandon the pipes on a second `TimeoutExpired` (close them).
4. [HIGH] Read partial output: from files after the kill, or `e.stdout`/`e.output` (bytes!) on `TimeoutExpired` (docs: bytes even with `text=True`; may be None). Decode with `.decode("utf-8", errors="replace")`.
5. [HIGH] Encoding: set `env["PYTHONUTF8"]="1"` (3.7+, UTF-8 mode) and `env["PYTHONIOENCODING"]="utf-8:replace"`; use `encoding="utf-8", errors="replace"` on the parent side when `text=True`; on Windows the console code page is otherwise cp1252/cp437 and `UnicodeEncodeError` in the child corrupts reports. Also set `PYTHONUNBUFFERED=1` so partial output exists at kill time.
6. [CRITICAL] Environment scrubbing: build the child env from an allowlist, not `os.environ.copy()` minus a denylist. Windows needs `SystemRoot`, `SYSTEMDRIVE`, `PATHEXT`, `COMSPEC`, `TEMP`, `TMP`, plus `PATH`; losing `SystemRoot` breaks `socket`/`ssl`/`random` on Windows. POSIX: `PATH`, `HOME` (point to sandbox temp), `LANG=C.UTF-8`, `TMPDIR`. Add `PYTHONDONTWRITEBYTECODE=1`, `PYTHONHASHSEED=0` (optional), `PYTHONPATH=<sandbox src>` explicitly, `PIP_DISABLE_PIP_VERSION_CHECK=1`, `NO_COLOR=1`, `CI=1`. Drop everything matching `*TOKEN*, *KEY*, *SECRET*, *PASSWORD*, *CREDENTIAL*, AWS_*, GITHUB_*, ANTHROPIC_*, OPENAI_*`; also remove `PYTEST_ADDOPTS` unless intended and `PYTEST_PLUGINS`. Run the interpreter as `sys.executable -m pytest`, with `-I` is NOT usable with `-m pytest` expectations for the cwd import (it removes cwd from sys.path and ignores PYTHON* env vars), so prefer `-P` (3.11+) or explicit `PYTHONPATH`.
7. [HIGH] pytest command skeleton: `[sys.executable, "-m", "pytest", "-p", "no:cacheprovider", "-p", "no:randomly"?, "--junitxml=<abs>/junit.xml", "-o", "junit_family=xunit2", "--rootdir=<sandbox>", "-q", "--tb=short", "-x"?, "--color=no", "--basetemp=<sandbox>/.bt", "--import-mode=importlib"?, "-W", "error"?, <test paths>]`. `-p no:cacheprovider` stops `.pytest_cache` writes (read-only sandbox, no cross-run leakage). Use `-o addopts=""` to neutralise repo `addopts`, and `--confcutdir=<vault tests dir>` + `-c <your own ini>` so the repo cannot change gate behaviour through `pytest.ini`/`pyproject.toml`/`setup.cfg`/`tox.ini` (pytest's `-c file` overrides ini discovery; recall).
8. [HIGH] Plugin loading: `PYTEST_DISABLE_PLUGIN_AUTOLOAD=1` (documented) stops arbitrary third-party entry-point plugins (including malicious or flaky ones installed in the venv) but ALSO disables useful ones (`pytest-timeout`, `pytest-xdist`, `pytest-cov`, your recorder if installed by entry point); then load exactly what you need with explicit `-p pytest_timeout -p xdist` / `-p mymodule` (module must be importable, so put it on `PYTHONPATH`). `-p` early-loading runs before conftest discovery. `--noconftest` (listed in pytest `--help`; recall) skips all `conftest.py`, which makes fixtures defined there disappear: tests fail with "fixture not found", so use it only if the vault tests are self-contained; `--noconftest` does not stop `-p` plugins or `pytest_plugins` declarations in test modules.
9. [CRITICAL] Result decision table (never trust stdout parsing alone): pass iff `returncode == 0` AND junit XML exists, parses, `tests` attribute total > 0 (sum over `<testsuite>`), `failures + errors == 0`, and the number of passed tests >= required count from the manifest of protected tests. Exit 5 => FAIL ("no tests collected" — e.g. wrong path, `-k` filter, import-skipped module); also treat all-skipped (`tests == skipped`) as FAIL, and 0 with `xfail`-only as suspicious. Exit 1 => tests failed (parse junit for IDs); 2 => interrupted/timeout (record as FAIL, not infra), 3 => internal error (infra/plugin bug), 4 => usage error (gate bug); timeout is your own state, returncode after kill is -9/-15 (POSIX) or the `TerminateProcess` code (Windows). Parse with `xml.etree.ElementTree`; the file is absent when pytest crashed early, so absent => FAIL. `--junitxml` is written at session end, so a hard kill leaves no file (use `-o junit_logging=no`; keep `-rA` or a `-p` plugin writing results incrementally for forensic partials).
10. [HIGH] Per-test timeout as defence in depth: `pytest-timeout` (`--timeout=60 --timeout-method=thread` on Windows, since `signal` method is POSIX-only; recall) loaded explicitly with `-p pytest_timeout`; outer wall-clock kill stays authoritative.
11. [MEDIUM] Make the child's cwd the sandbox and `stdin=DEVNULL` (a test calling `input()` otherwise hangs).
12. [MEDIUM] Do not `shell=True`; pass list args; on Windows avoid `.bat/.cmd` shims for the interpreter.

### Gaps

## Q6. `shutil.copytree`, read-only files, long paths, speed, `TemporaryDirectory` cleanup

### Takeaway
`copytree` aggregates failures into one `shutil.Error` at the end, follows symlinks by default (copying content), and uses `copy2`. Cleanup on Windows fails on read-only `.git` objects and open handles; use `rmtree(onexc=...)` (3.12+) / `onerror` (<3.12) and `TemporaryDirectory(ignore_cleanup_errors=True)`.

### Cited Findings
- `shutil.copytree(src, dst, symlinks=False, ignore=None, copy_function=copy2, ignore_dangling_symlinks=False, dirs_exist_ok=False)`: files via `copy2()`, directory perms/times via `copystat()`; `symlinks=False` copies linked file contents (not links); dangling symlinks add an entry to the aggregated `Error` unless `ignore_dangling_symlinks=True`; `Error` is an `OSError` subclass whose argument is a list of 3-tuples `(srcname, dstname, exception)`, raised "at the end of the copy process"; `dirs_exist_ok` added 3.8; `ignore` callable receives `(directory, os.listdir contents)` and returns names to skip; `shutil.ignore_patterns('*.pyc','tmp*')`. — [Python shutil docs](https://docs.python.org/3/library/shutil.html)
- `shutil.rmtree(path, ignore_errors=False, onerror=None, *, onexc=None, dir_fd=None)`: `onexc` added 3.12 (`onerror` deprecated, gets `exc_info`); Python 3.13: ignores `FileNotFoundError` for all but the top-level path. The docs give the Windows read-only recipe: `def remove_readonly(func, path, _): os.chmod(path, stat.S_IWRITE); func(path)` used as `shutil.rmtree(directory, onexc=remove_readonly)`. — [Python shutil docs](https://docs.python.org/3/library/shutil.html)
- `TemporaryDirectory(..., ignore_cleanup_errors=True)` (3.10+) ignores "any unhandled exceptions during... cleanup (such as a `PermissionError` removing open files on Windows)" and deletes the rest best-effort; `delete=False` (3.12+) keeps the directory for debugging. Warning: "Cleanup is not robust against the tree being modified while it is removed. Files outside of the tree may have their permissions and file flags reset." — [Python tempfile docs](https://docs.python.org/3/library/tempfile.html)

### Inferences
1. [HIGH] Copy policy: exclude `.git`, `__pycache__`, `.pytest_cache`, `node_modules`, `.venv`, `*.db*` using `ignore=shutil.ignore_patterns(...)`, or copy only a tracked-files list from `git ls-files -z` (best for a "worktree" gate: avoids read-only `.git/objects` entirely, and ignores untracked secrets such as `.env`). A git *worktree* has a `.git` *file* pointing outside the sandbox; do not copy it (a gate that runs `git` inside would operate on the real repo).
2. [HIGH] Symlinks: use `symlinks=True` to reproduce links verbatim only after validating targets stay inside the tree (otherwise a link to `/etc` or `~/.ssh` is dereferenced into the sandbox when `symlinks=False`, a secret-exposure/escape vector). Safest: skip links (custom `copy_function` that raises/skips when `os.path.islink(src)`; `ignore` is called with names only, so check `os.path.islink(os.path.join(dir, name))` inside it). On Windows, creating symlinks needs privilege/Developer Mode: `OSError WinError 1314`; junctions need no privilege.
3. [HIGH] Catch `shutil.Error` from copytree and fail the gate (partial copy = invalid evidence); do not swallow `e.args[0]`.
4. [HIGH] Windows long paths: copying deep trees (`node_modules`) can exceed 260 chars unless LongPathsEnabled; prefix with `\\?\` + absolute normalised path for `src`/`dst` (Python 3.6+ handles long paths when the OS setting is on; recall) and keep the sandbox root short (`%TEMP%\g<8 hex>`) to leave headroom; pytest `--basetemp` also short.
5. [MEDIUM] Speed: `copy2` copies metadata and is slow on NTFS/Defender-scanned dirs and very slow across /mnt/c; use `copy_function=shutil.copy` (or a plain `copyfile`) when mtimes don't matter; try `os.link` hardlinks for *immutable* inputs only (vault tests read-only); NEVER hardlink files the tests may modify or mutation tools may edit (it mutates the source). Reflinks: `cp --reflink=auto` on btrfs/XFS (not ext4, not NTFS); WSL2 ext4 has none. Python 3.14 adds none that I can confirm; `shutil.copy_file_range`-style fast paths already exist in `copyfile` on Linux 3.8+ (`os.sendfile`; recall). Keep the sandbox on the same FS as the source for cheap `os.replace`/hardlink.
6. [MEDIUM] Cleanup helper: `def _rm(func, path, exc): os.chmod(path, stat.S_IWRITE); func(path)`; call `shutil.rmtree(p, onexc=_rm)` on >=3.12 and `onerror=lambda f,p,e: _rm(f,p,e)` below (signature differs: 3.11- passes `exc_info` tuple); retry 3x with `time.sleep(0.2*2**i)` for Windows AV/handle races; final fallback `ignore_cleanup_errors=True` and write the leftover path to a janitor list so a startup sweep deletes it.
7. [MEDIUM] Make the sandbox read-only for inputs where possible (vault dir `chmod a-w` — advisory on Windows, where the readonly attribute doesn't stop directory ops) and verify post-run that vault files are byte-identical (hash before/after) as tamper evidence.
8. [MEDIUM] Never build the temp dir inside the worktree being copied (infinite recursion); place with `tempfile.mkdtemp(prefix="gate-", dir=<short trusted base>)`.

### Gaps
- Speed numbers for copytree on NTFS vs ext4 vs 9p not measured/found; hardlink and reflink behaviour from recall.
- Python 3.12+ `Path.is_junction`, Windows privilege details for symlinks: recall only.

## Q7. pytest plugin recording frame locals on failure (JSONL, xdist, redaction, token budget)

### Takeaway
Use a new-style `@pytest.hookimpl(wrapper=True)` on `pytest_runtest_makereport` (pluggy >= 1.2, pytest >= 7.4/8; keep an old-style `hookwrapper=True` fallback only if you must support old pytest), write one JSONL file per PID (merge afterwards), redact by name and by entropy, cap every repr with a hard budget, and serialise the record to JSON FIRST then truncate the *data* (not the JSON text) so every line stays valid.

### Cited Findings
- pytest docs show the new-style wrapper: `@pytest.hookimpl(wrapper=True)` on a generator that "yields exactly once"; `res = yield` raises if the underlying hook raised; the wrapper "needs to return a result for the hook, or raise an exception" (simplest: `return (yield)`); exceptions can be handled by `try/except/finally` around `yield`; mutating a mutable result is allowed but "it's probably better to avoid it". The fetched page does not mention the old-style `hookwrapper=True`. — [pytest: writing hook functions](https://docs.pytest.org/en/stable/how-to/writing_hook_functions.html)
- xdist: env var `PYTEST_XDIST_WORKER` holds the worker name (e.g. `"gw2"`); fixture `worker_id` returns `"master"` when xdist is disabled (`-n0`/no `-n`); `get_xdist_worker_id()` exists; each worker "will perform its own collection and execute a subset of all tests"; the docs' own pattern for logging is a per-worker file (`tests_gw0.log`, `tests_gw1.log`...) selected via `PYTEST_XDIST_WORKER` in `pytest_configure`; shared data coordination uses a lock file in the shared tmp dir. — [pytest-xdist how-to](https://pytest-xdist.readthedocs.io/en/stable/how-to.html)
- Plugin autoload and `-p` rules as in Q5. — [pytest: writing plugins](https://docs.pytest.org/en/stable/how-to/writing_plugins.html)

### Inferences
1. [HIGH] Hook choice: to capture the failing frame you need the traceback objects, available at `pytest_runtest_makereport(item, call)` via `call.excinfo` (an `ExceptionInfo`; `call.excinfo.tb` is the raw traceback; `call.excinfo.traceback` is pytest's wrapped list of `TracebackEntry` with `.frame.f_locals`, `.lineno`, `.path`). New style:
   ```python
   @pytest.hookimpl(wrapper=True)
   def pytest_runtest_makereport(item, call):
       report = yield
       if call.when in ("setup","call") and call.excinfo is not None and report.failed: record(...)
       return report
   ```
   Old style (`@pytest.hookimpl(hookwrapper=True)` with `outcome = yield; report = outcome.get_result()`) still works in pluggy 1.x/pytest 8 but is deprecated-style; do not mix. Alternative hook `pytest_exception_interact(node, call, report)` runs only for failures/errors and avoids the `if`, but is not called with `--pdb`-less setups in all cases (recall: it is called for failures and errors, and by `--pdb`); `makereport` is more predictable. Also consider `pytest_runtest_logreport` for simple reporting without locals.
2. [HIGH] Do the capture inside the hook, not later: frames hold references until the excinfo is dropped; after `makereport` pytest may clear tracebacks. Collect `f_locals` only for the innermost N (e.g. 3) frames inside the repo/sandbox (skip site-packages and pytest internals using `entry.path`), and never mutate locals. Accessing `frame.f_locals` can trigger `__getattr__`/descriptors only on repr, not on dict creation (CPython <=3.12 snapshot; 3.13 returns a write-through proxy for optimised frames per PEP 667, so copy with `dict(frame.f_locals)` immediately; recall).
3. [CRITICAL] Hostile objects: wrap each `repr` in a guard: `reprlib.Repr` with `maxstring`, `maxother`, `maxlevel`, `maxlist`; plus try/except `BaseException`-minus-`KeyboardInterrupt`; protect against huge objects by type-checking first (`len` via `type(obj).__len__` only for builtins), never `str()` a numpy/pandas object without bounds; recursion via `sys.getrecursionlimit` guard and `RecursionError` catch. A hard wall-clock cap per repr cannot be enforced in-thread without `signal.setitimer` (POSIX main thread only); on Windows use a bounded-repr whitelist (builtin scalars, list/tuple/dict/set with limits; everything else is `"<TypeName at 0x..>"` without calling user `__repr__`). That is the only robust policy against hostile `__repr__` that sleeps forever; call user `__repr__` only for an allowlist of module prefixes if you must.
4. [CRITICAL] Redaction: (a) by variable/key name, case-insensitive regex `(pass(word|wd)?|secret|token|api[_-]?key|auth(orization)?|cookie|session|credential|private[_-]?key|bearer|dsn|conn(ection)?[_-]?str)`; apply recursively to dict keys; (b) by value: patterns `AKIA[0-9A-Z]{16}`, `ghp_[A-Za-z0-9]{36}`, `sk-[A-Za-z0-9]{20,}`, JWT `eyJ[\w-]+\.[\w-]+\.[\w-]+`, `-----BEGIN [A-Z ]*PRIVATE KEY-----`, `Bearer\s+\S+`, URLs with `://user:pass@`; (c) entropy: tokens of length >= 20 with Shannon entropy > ~4.0 bits/char over `[A-Za-z0-9+/=_-]` replaced by `<redacted:high-entropy>`; accept false positives (hashes, UUIDs: allowlist `uuid`/hex40 optional). Redact BEFORE truncation, and redact `os.environ` values (`item.config`, `monkeypatch` locals) wholesale. The sandbox env scrubbing in Q5 is the first line; this is the second.
5. [CRITICAL] Concurrency: do NOT have xdist workers append to one file. POSIX `O_APPEND` writes with a single `write()` of a small buffer are effectively atomic between processes on local filesystems in practice (POSIX guarantees atomic position+write, atomicity of content for regular files is implementation-behaviour; PIPE_BUF 4096 atomicity applies to pipes, not files), but Python's buffered `open("a")` may split a record across `write()` calls, and Windows `O_APPEND` emulation in the CRT is not atomic across processes. Pattern: file name `locals-{os.getpid()}-{PYTEST_XDIST_WORKER or 'master'}.jsonl` in a run directory (`<run>/locals/`), opened with `buffering=1` or explicit `os.write(fd, line_bytes)` on an `os.open(..., O_WRONLY|O_APPEND|O_CREAT)` fd, `flush()` after each record, close in `pytest_sessionfinish`/`atexit`; a merge step (controller `pytest_sessionfinish` or the gate after the run) concatenates files sorted by `(ts_ms, pid, seq)` and skips non-parsing lines (a partial last line from a killed worker). Dir path communicated through env var set by the gate, or via `config.option`/`-o`; workers inherit env. On xdist workers, `pytest_configure` runs in each worker (the xdist docs' own logging example relies on it), so initialise per-process state there; `config.workerinput` exists only on workers, `hasattr(config, "workerinput")` distinguishes them (recall).
6. [CRITICAL] 400-token budget: the budget applies to the record's *serialised text*. chars/4 is the standard rough heuristic for English/code (about 4 chars per token; real tokenisers vary, code and JSON punctuation tokenise closer to ~3 chars/token, non-ASCII worse), so use `budget_chars = 400*3 = 1200` as the conservative cap, or count with a real tokenizer if one is allowed; mark the heuristic as an estimate in the spec. Truncating the JSON string at char N produces invalid JSON (unterminated string, split escape `\u00` or UTF-8 surrogate) and an invalid JSONL line. Fix: build a Python structure, then iterate: `line = json.dumps(rec, ensure_ascii=True, separators=(",",":"), default=str)`; while `len(line) > budget_chars`: shrink the data deterministically (drop least-informative locals first, reduce per-value `maxstring` 200 -> 80 -> 32, reduce frames 3 -> 1), set `"truncated": true`, `"dropped": n`; final fallback minimal record `{"test":..., "exc":..., "truncated":true}`; re-serialise and assert `json.loads(line)` before writing; one record per line, `"\n"` terminator, newline characters inside strings escaped by `json.dumps` (never write raw `\n`; `ensure_ascii` keeps lines single-line even for U+2028).
7. [HIGH] Write failures must never fail the test run: wrap the whole hook body in `try/except Exception` and increment a counter; report counter at sessionfinish. The plugin must not change `report.outcome`.
8. [MEDIUM] pytest 8/9 notes: do not use removed `py.path` hook args (`path` -> `collection_path` in collection hooks, 8.x); `pytest_runtest_makereport` signature `(item, call)` unchanged; `report.failed` for `call.when=="setup"` errors counts as error; with `--tb=native`/`-p no:logging` no effect on capture. Verify pytest 9 deprecations (e.g. old-style hook wrapper warnings, `pytest.warns` behaviour) against the changelog (not fetched).
9. [MEDIUM] Register the plugin by `-p module_name` (explicit) when `PYTEST_DISABLE_PLUGIN_AUTOLOAD=1`; for xdist, workers need the plugin importable too: `-p` options are propagated to workers (recall), and `PYTHONPATH` env is inherited.
10. [MEDIUM] `sys.monitoring` (3.12+) not needed: tracebacks already contain frames; avoid `sys.settrace` (slow, breaks coverage).

## Q8. Node ESM + Playwright Chromium via CDP: resolution, install checks, headless behaviour, determinism, exit codes, Windows vs WSL2

### Takeaway
Bare-specifier ESM imports resolve relative to the importing file's location, so a script outside the project that has `playwright` cannot `import "playwright"`; resolve it explicitly with `createRequire(...)` or `import(pathToFileURL(...))`. Never rely on `networkidle`; use web-first assertions and `page.clock` for deterministic time; always close the browser in `finally` and set `process.exitCode` rather than calling `process.exit()` mid-cleanup.

### Cited Findings
- Playwright docs mark `waitUntil: 'networkidle'` as "DISCOURAGED consider operation to be finished when there are no network connections for at least 500 ms" and say "Don't use this method for testing, rely on web assertions to assess readiness instead." — [Playwright Page API](https://playwright.dev/docs/api/class-page)
- `page.goto` timeout: "Defaults to `0` - no timeout" in that API page (default can be changed via `navigationTimeout` in the config; with the raw library the default for navigation is 30 s from `page.setDefaultNavigationTimeout`/`setDefaultTimeout`, recall; the fetched text says 0). Treat as an unresolved conflict: always pass `timeout` explicitly. — [Playwright Page API](https://playwright.dev/docs/api/class-page)
- Clock API: `page.clock.install()` must be called first; then `pauseAt`, `fastForward`, `runFor`, `resume`; `setFixedTime` is the recommended approach for a fixed `Date.now()`; `setSystemTime` is "only recommended for advanced use cases". Calling methods out of order gives "undefined behavior". `page.clock` overrides `requestAnimationFrame`, `cancelAnimationFrame`, `setTimeout`, `clearTimeout`, `setInterval`, `clearInterval`, `requestIdleCallback`, `cancelIdleCallback`; `runFor` fires "all timers and animation frames". — [Playwright Clock](https://playwright.dev/docs/clock)

### Inferences
1. [HIGH] ESM resolution: Node resolves bare specifiers by walking `node_modules` upward from the importing file, NOT from `process.cwd()` and not via `NODE_PATH` (ignored for ESM). Options: (a) put the script inside the project dir; (b) `import { createRequire } from "node:module"; const require = createRequire(path.join(PROJECT_DIR, "package.json")); const { chromium } = require("playwright");` (works, CJS entry); (c) `const { chromium } = await import(pathToFileURL(require.resolve("playwright")).href)` or resolve `playwright/index.mjs` (ESM entry); on Windows you MUST use a `file://` URL (`pathToFileURL`) because `C:\...` is parsed as protocol `c:`. `import.meta.resolve` with a parent URL argument needs `--experimental-import-meta-resolve` on older Node (stable-ish in 20+/22; recall). Fail with a clear message if resolution throws `ERR_MODULE_NOT_FOUND` / `MODULE_NOT_FOUND` (exit code 2 = environment).
2. [HIGH] Browser install check: `chromium.executablePath()` returns the expected path even if not installed; verify with `fs.existsSync(chromium.executablePath())` before launch; otherwise tell the user `npx playwright install chromium` (add `--with-deps` on Linux/WSL2; needs apt and sudo, which is a human-only step). Browsers live under `%USERPROFILE%\AppData\Local\ms-playwright` (Windows) or `~/.cache/ms-playwright` (Linux); `PLAYWRIGHT_BROWSERS_PATH` overrides; a Windows install is not visible in WSL2 and vice versa (separate OS homes), so install per side. Version pairing: each Playwright version expects a specific Chromium build (browser revision), so a stale `ms-playwright` yields "Executable doesn't exist". (recall)
3. [HIGH] Launch for CI/sandbox: `chromium.launch({ headless: true, timeout: 30000, args: [] })`; on Linux/WSL2 as root or in containers `--no-sandbox` is sometimes needed (security tradeoff; avoid unless forced); if `/dev/shm` is small use `--disable-dev-shm-usage`. Playwright's new headless mode uses the full-browser code path (`chromium-headless-shell` for old headless); behaviour of rAF in headless: frames still run but timing is not tied to a display vsync; background/occluded pages can be throttled (timers clamped to 1 s, rAF paused for hidden pages) — for a visible-less headless page Playwright keeps pages "focused/foreground" via emulation, but multiple tabs can throttle; open one page per context and bring to front (`page.bringToFront()`). (partly recall; verify)
4. [HIGH] Determinism: prefer `page.clock.install({ time })` then `page.clock.runFor(ms)` / `fastForward` / `pauseAt` to drive timers and rAF (documented above), instead of real `waitForTimeout`; `Date.now`, `performance.now` are also faked by `clock.install` (recall). For CSS/Web animations and the CDP route: `const cdp = await page.context().newCDPSession(page); await cdp.send("Animation.enable"); await cdp.send("Animation.setPlaybackRate", { playbackRate: 0 })` (pauses) or `Animation.seekAnimations` / `Animation.setTiming` to step (CDP protocol names; recall, check the DevTools protocol docs). Also `page.emulateMedia({ reducedMotion: "reduce" })` and injecting `* { animation: none !important; transition: none !important; }` for screenshots; `expect(page).toHaveScreenshot({animations:"disabled"})` is for the test runner only. CDP sessions are Chromium-only.
5. [HIGH] Readiness: replace `waitUntil: "networkidle"` with `waitUntil: "load"` or `"domcontentloaded"` + an explicit app signal (`await page.waitForFunction(() => window.__READY__ === true, null, { timeout })` or `locator.waitFor()`), because long-lived connections (websocket, SSE, analytics polling, HMR) keep "idle" from ever occurring or fire early in the gap between requests.
6. [CRITICAL] Timeouts and cleanup: set `page.setDefaultTimeout(15000)`, `page.setDefaultNavigationTimeout(30000)`, pass `timeout` to every `goto`; add a global watchdog `const t = setTimeout(() => { process.exitCode = 124; /* then force close */ }, 120000)` and `t.unref()` not used (needs to fire); the browser launch inside `try`, `finally { await browser?.close().catch(()=>{}); }`. `browser.close()` also kills child renderer processes it launched; if the Node process is killed (gate timeout), Chromium orphans may remain — launch Node in its own process group/job (Q5), and register `process.on("SIGTERM"/"SIGINT", async () => { await browser.close(); process.exit(143) })` (Windows only emulates SIGINT/SIGBREAK).
7. [HIGH] Exit codes (document in spec): 0 success; 1 assertion/check failed (page behaved wrongly); 2 environment (module missing, browser not installed, launch failed); 3 timeout/navigation failure; 124 watchdog. Use `process.exitCode = n` and let the event loop drain after `finally`; call `process.exit` only after awaiting close. Handle `unhandledRejection` => exitCode 1 with message. Print results as one JSON object on the last stdout line so the Python gate can parse robustly irrespective of Chromium warnings on stderr.
8. [MEDIUM] Windows vs WSL2: no WSLg/X server is needed for headless; `headless: false` in WSL2 requires WSLg (Windows 11 has it by default on supported builds; not on Windows 10 or if disabled: failure "Missing X server or $DISPLAY"). Run the Node script on the same OS side as the Python gate and the files it reads; Playwright in WSL2 reaching a dev server on Windows localhost relies on WSL2 localhost forwarding/mirrored networking (`networkingMode=mirrored` in `.wslconfig`; recall) — prefer starting the server in the same OS. Do not mix `node.exe` (Windows) with a WSL project path (`\\wsl.localhost\`): slow, path-escaping issues, and the SQLite/WAL hazards of Q1 if they touch the DB.
9. [MEDIUM] If attaching to an existing Chrome over CDP rather than launching: `chromium.connectOverCDP("http://127.0.0.1:9222")`; bind to loopback only; remote debugging ports are an unauthenticated code-execution surface, never expose; `--remote-debugging-port` with a fresh `--user-data-dir`; Chrome 136+ ignores `--remote-debugging-port` on the default profile (recall; verify). `browser.close()` on a `connectOverCDP` browser disconnects, not closes, the external Chrome.
10. [MEDIUM] Pin `playwright` version in the project's `package.json` + lockfile (`npm ci`), use `"type": "module"` or `.mjs`, and require Node >= 20 LTS (Node 18 is EOL; recall).

### Gaps
- `page.goto` default timeout: the fetched API page says "Defaults to 0 - no timeout", while my recall is 30 s for the library defaults; unresolved, pass explicit timeouts.
- CDP `Animation.*` method names, headless rAF throttling specifics, `connectOverCDP` on Chrome 136+, WSLg availability, Node version policy: not verified from sources this session (Playwright `networkidle`/`clock` pages were the only Playwright sources read).
- Playwright "browsers" doc and release notes (browser install paths, headless shell) were not fetched.
