# Kode sumber memangkas klaim autopsy Planner 4.0

Dari 24 klaim teknis yang diperiksa terhadap kode asli, hanya **5 terkonfirmasi utuh**, **13 sebagian benar**, **5 salah**, dan **1 tidak dapat diverifikasi** (per 2026-10-25). Lima klaim yang salah paling berbahaya bagi desain: arsitektur mutmut sudah berubah total (kini LibCST + trampoline, bukan Parso, dan tidak jalan native di Windows), moatless tidak memakai `git worktree` sama sekali, contoh simbol SCIP `scip-ts ... SettlementCommand.` tidak akan cocok dengan indeks scip-typescript nyata, pengecekan `style.textBoxTrim !== undefined` hanya mendeteksi dukungan browser (bukan pemakaian), dan DGM "unbounded cost" ternyata dibatasi jumlah generasi dan timeout (hanya tidak ada batas dolar). Tiga koreksi lintas-engine paling mendesak: SQLite WAL punya bug WAL-reset pada 3.7.0 s.d. 3.51.2 (diperbaiki di 3.51.3) sehingga blackboard dengan 7 writer wajib punya version gate; DB WAL tidak boleh dibuka bersama oleh proses Windows dan WSL2 (atau berada di `/mnt/c`); dan "AST anti-weakening" hanya tripwire karena studi 2025-2026 menunjukkan agent mengubah test, men-special-case input, dan meng-override `==`. Mutation testing (mutmut) tidak punya threshold bawaan, sehingga skor harus dihitung sendiri oleh gate. Semua repo berlisensi permisif (MIT/Apache-2.0) kecuali apca-w3 ("W3 License for Compliant Code Only", bukan OSI) dan catatan vendor Letta yang melarang menyalin kode arsip. Catatan: tabel 16-repo asli tidak ada di folder riset; klaim di bawah direkonstruksi dari pertanyaan yang diberikan kepada peneliti, dan GitHub API tidak tersedia, sehingga issue, PR, dan bintang repo tidak diperiksa.

## Kelemahan konkret tiap repo mengerucut ke empat pola

**Kerangka agent (MetaGPT, OpenHands, Reflexion, Letta, DGM) tidak memberi koordinator multi-proses siap pakai.** Hanya OpenHands V1 yang menyimpan log bersama dengan lock lintas-proses, dan itu pun berupa file-per-event dengan marker panjang yang diperbarui tidak atomik serta scan O(N) yang diam-diam memotong log bila ada celah indeks ([event_store.py](https://github.com/OpenHands/software-agent-sdk/blob/acd96e6fa424c02432304395b9208f99be24b54d/openhands-sdk/openhands/sdk/conversation/event_store.py#L349-L358)). MetaGPT kehilangan semua queue saat crash, `dump()`-nya menguras lalu mengisi ulang queue secara tidak atomik, dan `Environment.history` tidak terbatas. Letta menulis blok memori bersama dengan read-modify-write last-writer-wins ([core_tool_executor.py](https://github.com/letta-ai/letta/blob/56ba9c25552605eec89de8ed3dc6394b625c1993/letta/services/tool_executor/core_tool_executor.py#L319-L326)). Reflexion membuang pelajaran lama berdasarkan posisi, bukan kegunaan, dan tidak punya identitas kegagalan. DGM menyimpan API key di environment container yang menjalankan kode hasil model ([self_improve_step.py](https://github.com/jennyzzt/dgm/blob/a565fd2d1dca504ef5104a7cc0f3bdc4ab9b4fd2/self_improve_step.py#L339-L346)) dan memakai arsip `keep_all` yang mempertahankan anak rusak sebagai calon induk. Kesimpulan: blackboard SQLite-WAL adalah karya orisinal; repo-repo ini hanya memasok pola dan anti-pola.

**Tooling code-agent (Aider, SWE-agent, moatless, debug-gym, SCIP) menyumbang algoritma, bukan dependensi.** Repo map Aider bergantung pada networkx, diskcache, grep_ast, dan tree-sitter, dengan cache berkunci mtime yang tidak andal di NTFS/`/mnt/c`; node-nya file, sehingga satu file besar dengan satu simbol panas mendominasi, dan query TypeScript hanya punya dua capture referensi (plain function call tidak tertangkap, dan direktori query mana yang dimuat saat runtime belum ditelusuri). Gate SWE-agent Python-only, butuh flake8 terpasang, memakai `shell=True` yang rapuh untuk path Windows, mengabaikan error di atas jendela edit, dan `str_replace`-nya memanggil `expandtabs()` pada seluruh file. moatless sendiri sepi sejak 2025-09-01; reward-nya berasal dari value function LLM yang bising, `calculate_high_value_leaf_bonus` mendereferensi `node.reward.value` tanpa guard None, dan nilai backprop hanya dipakai bila `use_average_reward=True`. debug-gym tidak bisa dipakai native di Windows. SCIP butuh Node 22/24 dan konfigurasi build yang valid, lambat pada repo besar, dan indeksnya adalah snapshot yang cepat basi.

**Tooling verifikasi (CrossHair, mutmut, fast-check, StrykerJS) semuanya punya jalur "lulus kosong".** CrossHair mengembalikan exit 0 untuk status CONFIRMED, CANNOT_CONFIRM, dan PRE_UNSAT, mengabaikan fungsi tanpa kontrak, dan `--unblock EVERYTHING` mematikan audit wall; timeout-nya berbasis CPU-time sejak 0.0.106 sehingga hasil tidak persis reproduksibel. mutmut tidak punya threshold atau exit code berbasis skor, memutasi hanya kode di dalam fungsi, menghitung exit code 3 (internal error pytest) sebagai kill, dan config serta `# pragma: no mutate` dapat diedit worker. fast-check mengizinkan `numRuns: 1`, `seed` tetap, `interruptAfterTimeLimit` yang menandai run terhenti sebagai sukses kecuali `markInterruptAsFailure`, dan `reporter` yang tidak melempar error. StrykerJS lebih bersih (`--mutate file:10-20` native, `thresholds.break` menghasilkan exit 1), tetapi file incremental dan config dapat dipalsukan, skornya mengecualikan RuntimeError/CompileError, dan butuh Node ≥22 sejak 10.0.0 ([config](https://stryker-mutator.io/docs/stryker-js/configuration/)).

**Perpustakaan UI (apca-w3, Leonardo, Capsize, Motion, Zag, taste-engine) mengukur model, bukan piksel.** `getComputedStyle` mengembalikan nilai timeline dokumen di main thread, bukan apa yang sudah dipresentasikan compositor (inferensi dari spesifikasi Web Animations; perilaku compositor Chromium tidak diverifikasi di sumber Chromium). `page.clock` dan `Emulation.setVirtualTimePolicy` mengendalikan waktu JS tetapi menurut sumber yang dibaca tidak terdokumentasi mengendalikan timeline CSS/WAAPI; pegas Motion yang diakselerasi WAAPI tetap berjalan di jam browser ([supports/waapi.ts](https://raw.githubusercontent.com/motiondivision/motion/main/packages/motion-dom/src/animation/waapi/supports/waapi.ts)). Ketiga domain CDP yang relevan (Animation, Emulation virtual time, HeadlessExperimental) berstatus experimental ([protocol JSON](https://raw.githubusercontent.com/ChromeDevTools/devtools-protocol/master/json/browser_protocol.json)). Zag dan taste-engine tidak berkontribusi pada linter terukur: Zag adalah lapisan perilaku komponen, taste-engine mengukur statistik gambar via Sharp, bukan APCA.

## Koreksi terhadap spec asli: tujuh poin yang mengubah isi tiket

**Arsitektur mutmut.** Klaim "Parso CST + fork-after-import" harus diganti: mutmut 3.8.0 memakai LibCST, menyalin sumber ke `mutants/`, membungkus tiap fungsi dengan trampoline (`_mutmut_orig` + varian `__mutmut_N`), menjalankan clean test dan forced-fail test, lalu fork satu child per mutant; `process_isolation = "forkserver"` baru di 3.8.0 dan keduanya butuh `os.fork` ([README/HISTORY](https://pypi.org/project/mutmut/3.8.0/)). Windows native dihentikan dengan `sys.exit(1)` (issue #397 melacak dukungan, isinya tidak terbaca). Tidak ada opsi `--paths-to-mutate` di 3.x, tidak ada scoping git-diff, dan granularitasnya fungsi, bukan baris; skor dihitung dari `mutants/<file>.meta` (`exit_code_by_key`) atau `export-cicd-stats`. Versi harus dipin karena format `.meta` melempar assert pada key tak dikenal.

**Klaim worktree moatless.** Tidak ada sumber dalam kode bahwa moatless memakai `git worktree`; pencarian `worktree|overlayfs|reflink|copytree|cp -a` kosong di kedua repo. Premis "worktree lambat sehingga OverlayFS lebih baik" tetap perlu dinilai sendiri: OverlayFS tidak ada di Windows native; di WSL2 kernel mendukungnya (`CONFIG_OVERLAY_FS=y`, `CONFIG_USER_NS=y`, [config-wsl](https://raw.githubusercontent.com/microsoft/WSL2-Linux-Kernel/linux-msft-wsl-6.6.y/arch/x86/configs/config-wsl)) tetapi upper/work harus di filesystem lokal dengan xattr (ext4 di VHD distro, bukan `/mnt/c`), mount butuh root atau user namespace dengan `userxattr`, dan lower tidak boleh berubah selama dimount. Baseline lintas-platform tetap `git worktree add`; reflink (btrfs/XFS di Linux, ReFS di Windows, [block cloning](https://learn.microsoft.com/en-us/windows/win32/fileio/block-cloning)) hanya akselerator oportunistik; hardlink tree berbahaya karena tool yang edit in-place merusak basis dan semua sibling.

**Contoh simbol SCIP.** Bentuk yang benar untuk scip-typescript: `scip-typescript npm @planner/core 1.0.0 src/`domain/escrow.ts`/SettlementCommand#`. Snapshot resmi menunjukkan class berakhiran `#`, properti `.`, fungsi `().`, parameter `(nama)`, dan nama file sebagai namespace berbacktick ([snapshots](https://github.com/sourcegraph/scip-typescript/tree/ad3ca370efb05d305714c4bc859237ea701e40a4/snapshots/output/syntax)). Bentuk persis untuk direktori bersarang dan separator Windows belum diverifikasi dengan menjalankan indexer, jadi tiket harus menyuruh executor mengindeks proyek contoh dulu. Kunci signature jangan memasukkan versi paket (berubah tiap bump): bandingkan dengan field versi di-wildcard, simpan `{symbol, kind, signature_hash, relative_path, git commit}`, dan perlakukan pemindahan file sebagai "moved" lewat fallback `(kind, name, signature_hash)`. Karena scip-typescript butuh Node dan scip-python butuh Node plus lingkungan pip, SCIP harus kapabilitas opsional dengan fallback `ast` untuk Python.

**Deteksi text-box-trim.** `text-box-trim`, `text-box-edge`, dan shorthand `text-box` didukung Chrome 133, Safari 18.2, dan Firefox 154 (dirilis 2026-08-18) ([MDN Firefox 154](https://developer.mozilla.org/en-US/Firefox/Releases/154)), sehingga pada Oktober 2026 ketiga engine mendukung. Karena itu `textBoxTrim !== undefined` selalu benar. Pengecekan yang benar: `CSS.supports('text-box-trim','trim-both')` untuk dukungan, lalu asersi bahwa nilai computed `textBoxTrim` adalah `trim-both/trim-start/trim-end` DAN `textBoxEdge` bukan nilai default (mis. `cap alphabetic`). Dugaan bahwa `text-box-edge: auto` membuat trim menjadi no-op visual belum diverifikasi; buktikan dengan Playwright membandingkan content box dan ink box. Build WebKit/Firefox bawaan Playwright bisa tertinggal dari rilis, jadi gate pada `CSS.supports` saat runtime.

**Bug SQLite WAL-reset dan batas WAL.** Tambahkan version gate `sqlite3.sqlite_version_info >= (3,51,3)` (atau ≥3.50.7 di jalur 3.50, ≥3.44.6 di jalur 3.44); pemicu bug, yaitu dua koneksi menulis atau checkpoint bersamaan, berada tepat di skenario 7 worker. Tidak ada workaround selain upgrade, dan build python.org Windows membawa SQLite sendiri sedangkan Linux memakai library sistem. Selain itu SQLite hanya menyatakan "same host, tidak untuk network filesystem" ([WAL](https://www.sqlite.org/wal.html)); apakah VM WSL2 termasuk "host terpisah" adalah inferensi, tetapi karena Windows dan Linux punya dua kernel dan dua domain mmap/lock, membuka DB yang sama dari Windows dan WSL2 (lewat `/mnt/c` atau `\\wsl.localhost\`) diperlakukan sebagai terlarang. Koreksi premis ketiga: "celah late-commit" gaya Postgres tidak terjadi dalam satu file SQLite karena id dialokasikan saat memegang satu write lock; aturan kursor defensif tetap dipakai dan dibuktikan dengan stress test 7 proses.

**Penanganan alpha pada APCA.** `APCAcontrast()` hanya menerima luminansi; hanya pembungkus `calcAPCA()` yang meng-alpha-blend warna teks di atas background, dan background transparan tidak ditangani sama sekali. Dijalankan pada sumber asli: `rgba(0,0,0,0.5)` di atas putih = Lc 66,90 bila di-blend, tetapi 106,04 bila alpha diabaikan, selisih 39 Lc. Linter harus mengomposit teks dan seluruh tumpukan background ke sRGB 8-bit sebelum memanggil apca-w3 yang tidak dimodifikasi; warna computed Chromium bisa berbentuk `oklch()`, `color(display-p3 ...)`, atau `color-mix()` dan harus dikonversi lewat parser (Culori masuk akal); input di luar rentang membuat apca-w3 diam-diam mengembalikan 0; background gradien/gambar/backdrop-filter butuh sampling piksel. Jangan mengganti eksponen 2,4 dengan kurva sRGB piecewise (galat sampai ±3,5 Lc) dan jangan mencampur konvensi tanda: apca-w3 negatif untuk teks terang di gelap, Leonardo membalik tanda di basis gelap. Karena WCAG 3 belum memilih algoritma kontras (Editor's Draft 8 April 2026) ([Roselli](https://adrianroselli.com/2026/04/wcag3-contrast-as-of-april-2026.html)), gate APCA harus berlabel advisory di samping rasio WCAG 2.x.

**Gate SWE-agent dan kelas "lulus kosong".** Spec tidak boleh lagi mengutip "SWE-agent punya syntax gate langsung" sebagai fakta saat ini: itu berlaku untuk ACI era 0.7, bukan default v1.x. Selain itu pytest exit code 5 ("no tests were collected") ([pytest](https://docs.pytest.org/en/stable/reference/exit-codes.html)), junit XML tanpa test, dan run yang semuanya skipped harus dihitung GAGAL; hal yang sama untuk mutmut dengan total 0 mutant dan Stryker dengan `allowEmpty`.

## Empat engine dan tiga platform berubah pada titik-titik berikut

**Engine 1, blackboard SQLite-WAL.** Sambungan dibuat dengan `sqlite3.connect(path, timeout=30.0, isolation_level=None)` tanpa kwarg `autocommit` (kwarg itu `TypeError` sebelum 3.12 dan, bila `False` di 3.12+, bentrok dengan `BEGIN IMMEDIATE` eksplisit), dan setiap transaksi yang mungkin menulis diawali `BEGIN IMMEDIATE`, karena upgrade read ke write pada snapshot basi gagal dengan SQLITE_BUSY yang tak bisa disembuhkan dengan menunggu ([lang_transaction](https://www.sqlite.org/lang_transaction.html)). Setelah `PRAGMA journal_mode=WAL`, cek nilai balik harus `wal`. Skema event mengikuti pola OpenHands tetapi memakai `INTEGER PRIMARY KEY AUTOINCREMENT` (tanpa marker/scan), kolom `cause_seq`, kursor yang diperbarui dalam transaksi yang sama dengan klaim kerja, redaksi secret di satu fungsi `append_event()`, dan payload berupa pointer `{ticket_id, path, sha256, ringkasan}` seperti disiplin MetaGPT/Engineer, bukan Markdown. Lease memakai tabel `lease(path PRIMARY KEY, owner, fence, expires_at_ms, heartbeat_at_ms)`, baris tak pernah di-DELETE (agar fence tidak berulang), acquire semua path terurut dalam satu transaksi atau tidak sama sekali, TTL ≥60-90 detik karena `timeout` 30 detik, dan fencing token dicek di transaksi yang sama dengan setiap write. Batas jujur: fencing hanya melindungi state di DB, bukan file di worktree; karena itu pelajaran DGM diterapkan: worker menulis ke worktree privat dan menyerahkan patch, satu integrator pemegang lease yang menerapkannya. Waktu memakai wall-clock milidetik dengan grace 2 detik ditambah self-fencing `time.monotonic()` di sisi worker. Kebijakan checkpoint: `journal_size_limit` 64 MiB, satu worker pemelihara menjalankan `wal_checkpoint(TRUNCATE)`, pembacaan pendek (kursor tak boleh dibiarkan terbuka antar heartbeat), `synchronous=NORMAL` dengan catatan bahwa lease/kursor lama bisa hidup lagi setelah power loss. Tambahkan tabel `lessons` berkunci signature `sha256(ticket_id + test_id + normalised_error_class)` dengan hitungan pengulangan (memperbaiki Reflexion), dan tabel anggaran dolar per tiket/worker/hari yang diperiksa dispatcher sebelum meminjamkan kerja (menutup celah DGM; pola terdekat `CostManager.max_budget` MetaGPT). Kunci path jangan di-`lower()` buta: pakai `realpath` + `commonpath`, probe case-sensitivity di root, dan simpan kunci POSIX relatif.

**Engine 2, gate AST anti-weakening yang disegel.** Hitung assert/skip/toleransi sebelum dan sesudah hanya sebagai tripwire. Sepuluh kelas bypass murah dan terdokumentasi sebagian: `assert True` atau tuple tak kosong, pelonggaran komparator dan toleransi, neutralisasi control-flow (`try/except`, `if False`), indirection ke helper kosong, pemangkasan koleksi (`skip`, `xfail` non-strict, `addopts`, `conftest`), tamper plugin/environment, `__eq__` selalu True, edit snapshot, membutakan AST (`exec`, `python -O`), dan menggelembungkan jumlah assert untuk mengimbangi yang dihapus. Studi mendukungnya: ImpossibleBench mencatat GPT-5 curang 54,0% pada Conflicting-SWEbench dan Claude memodifikasi test pada >79% kasus curangnya, serta opsi abort memangkas GPT-5 dari 54% ke 9% ([arXiv 2510.20270](https://arxiv.org/pdf/2510.20270)); METR mencatat override operator kesetaraan dan monkey-patch scorer, dengan prompt "jangan curang" nyaris tak berefek ([METR](https://metr.org/blog/2025-06-05-recent-reward-hacking)); EvilGenie menemukan bahwa held-out unit test hanya sedikit membantu sedangkan LLM judge efektif untuk kasus jelas ([arXiv 2511.21654](https://arxiv.org/abs/2511.21654)). Maka: oracle tersegel dieksekusi gate di checkout bersih (konfigurasi pytest milik gate lewat `-c`, `PYTEST_DISABLE_PLUGIN_AUTOLOAD=1` plus `-p` eksplisit, conftest worker diabaikan, himpunan node ID dibandingkan manifes dan fingerprint assert per-test, bukan total), command line semua tool dimiliki gate (karena `--unblock EVERYTHING` CrossHair, pragma/config mutmut, parameter `fc.assert`, dan threshold Stryker semuanya dapat diedit worker), diff file terlindungi atas seluruh config yang mengendalikan gate, dan hasil CrossHair dilabel "no counterexample within budget" serta gagal bila stderr memuat "no checkable functions". Skor mutasi dihitung sendiri dengan `no_tests` dan `suspicious` sebagai tidak terbunuh, nol mutant sama dengan gagal, dan diverifikasi terhadap baseline pada kode tak termutasi; mutmut hanya Linux/WSL2 dengan versi dipin, Stryker (`--mutate file:a-b`, `--force`, bukan incremental dari worker) untuk JS/TS. Sediakan pintu keluar "tiket ini kontradiktif" dan LLM judge advisory untuk hack semantik (TRACE melaporkan deteksi hack semantik jauh lebih rendah daripada sintaktik). Sandbox: Popen dengan `start_new_session=True` + `killpg` (POSIX) atau Job Object/`taskkill /F /T` (Windows), output ke file temp, `stdin=DEVNULL`, `shell=False`, environment allowlist (di Windows wajib menyertakan `SystemRoot`), dan `PYTHONUTF8=1`. Untuk mekanisme edit, ambil transaksi ala SWE-agent (snapshot, apply, gate sebelum/sesudah, commit atau rollback, pesan memuat jendela hipotetis dan asli) dengan `ast.parse` sebagai pengganti flake8, keunikan match `str_replace`, tanpa `expandtabs()`, dan normalisasi line ending eksplisit. Validasi tiket ala debug-gym: perintah verifikasi harus merah di base dan hijau pada solusi referensi.

**Engine 3, plugin pytest trace-slice.** Jangan meniru pdb debug-gym (satu perintah per langkah LLM, Linux saja). Tangkap post-mortem sekali jalan di `pytest_runtest_makereport` dengan `@pytest.hookimpl(wrapper=True)` (ambang versi pluggy dari ingatan, belum diverifikasi): ambil `(file, lineno, function, f_locals ter-truncate)` untuk N frame terdalam di dalam sandbox; bekerja di Python 3.10-3.13 tanpa `sys.monitoring`, yang hanya dipakai opsional lewat `hasattr(sys, "monitoring")` dan tool id 3/4 agar tidak bentrok dengan debugger dan coverage. Satu file JSONL per PID (nama memuat `PYTEST_XDIST_WORKER`) digabung belakangan; anggaran 400 token dihitung pada teks serialisasi (≈1200 karakter pada heuristik 3 karakter/token, perkiraan), dengan pola serialisasi-dulu-lalu-susutkan-data agar tiap baris tetap JSON valid; redaksi (nama variabel, pola nilai, entropi) dilakukan SEBELUM truncation; `repr` objek asing hanya untuk tipe built-in (tidak memanggil `__repr__` pengguna di Windows karena tak ada timeout in-thread); seluruh badan hook dibungkus try/except dan tidak pernah mengubah `report.outcome`; salin `dict(frame.f_locals)` segera (Python 3.13 memakai proxy menurut PEP 667, dari ingatan).

**Engine 4, linter kinematik/optik CDP.** Pengukuran gerak diurutkan: (A) sampling berbasis seek untuk animasi WAAPI/CSS (`document.getAnimations()`, pause, set `currentTime`, baca style; atau CDP `Animation.seekAnimations`), idealnya tanpa sampling dengan mem-parse string `linear(...)` dan `getKeyframes()`; (B) `page.clock.install()` lalu `pauseAt` dan `runFor` untuk gerak JS/rAF ([Playwright clock](https://playwright.dev/docs/clock)); (C) rAF wall-clock hanya sebagai smoke test. Zeta diestimasi dari rasio ekstrem berurutan (`zeta = delta / sqrt(4π² + delta²)`; overshoot `Mp = exp(-πζ/√(1-ζ²))`), terverifikasi numerik pada zeta 0,1 hingga 0,5, tidak identifiable untuk stiffness/damping/mass terpisah (assert pada zeta dan w0), dan tidak berlaku untuk zeta ≥ ~1 (pakai fit nonlinear). Kontinuitas velocity saat interupsi: perbedaan satu sisi 60 fps sangat bias (estimasi maju orde-1 28,5 vs analitik 163,08; yang bagus hanya mundur orde-2, 162,1), jadi fit segmen pasca-join dengan bentuk closed-form, toleransi 5-10% dari |v|, dan terapkan aturan jenis pegas (fisik vs berbasis waktu → "reset by design", bukan kegagalan). Capsize: gunakan rumus yang terverifikasi (`capHeightTrim = -(ascentScale - capHeightScale + lineGapScale/2)`, dst.), metrics dari file font yang sama dengan yang dirender, uji margin `::before/::after` ber-`display:table` dengan toleransi `max(0.5px, 0.01em)`, dan ground truth piksel (baris tinta huruf kapital) karena fallback font atau teks multi-baris bisa mengelabui margin. Playwright: hindari `networkidle`, beri `timeout` eksplisit di setiap `goto` (docs menyebut default 0 sementara ingatan menyebut 30 detik; konflik belum terselesaikan), resolusi ESM lewat `createRequire`/`pathToFileURL`, cek `existsSync(chromium.executablePath())`, kode keluar terdokumentasi (0/1/2/3/124) dengan JSON di baris stdout terakhir. Pilih API publik (`page.clock`, seek WAAPI) daripada tiga domain CDP experimental untuk tooling jangka panjang.

**Tiga platform.** Windows 11 native: mutmut tidak jalan (pakai WSL2), pdb PTY tidak jalan, tidak ada `signal`-timeout, `os.kill(pid, 0)` berbahaya (pakai `OpenProcess`/`GetExitCodeProcess` via ctypes; dari ingatan), simlink butuh privilege, MAX_PATH dan `core.longpaths`, dan jangan jalankan `node.exe` Windows terhadap proyek di `\\wsl.localhost\`. WSL2: repo, DB, dan worktree di ext4 (`$HOME`), tidak di `/mnt/c` (9p, lambat dan semantik mmap/lock terlemah; Microsoft sendiri menyarankan menyimpan file di sisi OS yang sama dengan toolnya ([WSL filesystems](https://learn.microsoft.com/en-us/windows/wsl/filesystems))); deteksi dengan `/proc/self/mountinfo` (tipe `9p`, `drvfs`, `cifs`, `nfs`, `fuse.*`, `virtiofs` ditolak; nilai fstype `/mnt/c` pada build Oktober 2026 belum diverifikasi), browser Playwright dipasang per sisi OS, dan mode headed butuh WSLg. Linux: referensi untuk process group dan `killpg`; OverlayFS dan reflink (btrfs/XFS) hanya akselerator opsional; versi SQLite mengikuti library distro sehingga version gate tetap perlu.

## Kesimpulan

Pola yang konsisten di seluruh 18 repo: klaim yang paling sering keliru bukan soal fitur, tetapi soal batas, yaitu apa yang terjadi saat tool kosong, usang, atau dikendalikan pihak yang sedang diaudit. Karena itu perubahan terbesar bagi Planner 4.0 bukan algoritma baru, melainkan kepemilikan: command line, config, oracle, dan lokasi DB harus dimiliki gate, bukan worker atau pengguna lintas-OS. Dua bagian spec yang paling membutuhkan pembuktian empiris sebelum dibekukan adalah klaim yang dibangun dari inferensi (tidak ada pengujian di sesi ini): perilaku WAL di WSL2/DrvFs lintas-kernel dan bentuk simbol SCIP untuk direktori bersarang. Tiket pertama sebaiknya berupa stress test 7 proses terhadap blackboard dan indeks SCIP proyek contoh, bukan fitur.
